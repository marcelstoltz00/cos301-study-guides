For each scenario, choose the best deployment strategy (canary, blue-green, rolling or none of the above). Then, in one sentence, justify your choice by naming the property of that strategy that the scenario specifically requires.

Marks: 1 for the correct strategy, 1 for a justification that names the distinguishing property.


  1. A fintech company is deploying a new version of its payment-processing service. The new version contains a refactor of the fraud-detection model. The team wants to compare the new model's false-positive rate against the old one using real production traffic, but they are not yet confident the new model is correct. The service is stateless, and computational power is not an issue. They need to be able to abort the rollout in seconds if metrics degrade. [2 marks]
  2. A team runs a fleet of 200 stateless web-server instances behind a load balancer. They are deploying a CSS-only change. Cluster capacity is tight; they cannot afford to spin up a second full fleet of 200 instances. The change has been reviewed and tested; the team is confident it is correct. They want zero downtime. [2 marks]
  3.  A team is shipping a new release that includes a backwards-incompatible database schema change. The new application code cannot read the old schema, and the old application code cannot read the new schema. The team wants to be able to roll back instantly if the release is bad. [2 marks]
Answer
1.Blue-Green-> we can send production traffic to the green deployment, get enough throughput to verify if the model is correct, and if we want to rollback we can just switch over the the blue deployment again,ensuring we use the old deployment. The main reason this deployment is the best is because computational power is not an issue, and Blue-Green essentially has double deployments.
2.Rolling->Due to the fact that the change is css only, and that its been tested, we can use a rolling deployment to replace each one of the 200 instances one by one, gradually updating the whole fleet. The benefit is that there will be no downtime due to the fact that 199 instances will always be running.
3.Canary ->We slowly update one server at a time, monitring to check if the release went badly. If it did we simply rollback the recently updated servers.

  2. correct, not the distinguishing property (1/2)

Question 11

Essay

A company wants to build an Online Food Delivery System. Customers place orders using a mobile app or website. Orders are sent to restaurants for preparation, payments are processed through an external payment gateway, and delivery drivers receive delivery requests through their own mobile app. The system must handle thousands of users during peak times and continue operating even if one service fails.


Answer the following questions:

  1. Recommend the most suitable software architecture pattern for this system. (2 marks)
  2. Give three reasons why this architecture is appropriate for the scenario. (3 marks)
Answer
  1. Microservices -> will be the most suitable due to the range of different applications
  2. The first reason is that when we have peak traffic, we can just spin up multiple instances of the same microservice, ensuring that traffic gets handled effecitively.

the second reason is that we have various services that need to operate independently, such as the the external gateway, the website, the customers app, the delivery drivers app.Each one of them requires their own frontend,logic and processes.

the last reason is that when one service fails, the rest of the services are unaffected by the service that failed.
