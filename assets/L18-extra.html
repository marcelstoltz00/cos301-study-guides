UI Architecture Patterns: MVC, MVP, MVVM, MVT

Exam rule: focus on ownership: who receives input, who owns UI state, and who decides rendering flow.

MVC Core Split

PartResponsibilityTypical role
ModelDomain data and business rulesState and logic
ControllerReceives input and decides what happens nextFlow control
ViewRenders model data for the userPresentation
flowchart LR U[User] --> V[View] V --> C[Controller] C --> M[Model] M --> V

MVVM vs MVT

FeatureMVVMMVT
Main intermediaryViewModelView
Rendering styleClient-side, data-bound UIServer-side template rendering
Common contextAngular, Vue, WPF-like patternsDjango and similar frameworks
flowchart TB subgraph MVVM A1[View] --> B1[ViewModel] B1 --> C1[Model] C1 --> B1 B1 --> A1 end subgraph MVT A2[HTTP Request] --> B2[View] B2 --> C2[Model] C2 --> B2 B2 --> D2[Template] D2 --> E2[Rendered HTML] end

MVP Positioning

PatternControl flowBest fit
